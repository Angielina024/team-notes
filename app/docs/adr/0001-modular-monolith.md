# ADR 0001: Модульний моноліт для Team Notes

Статус: прийнято · Дата: 2026-11-13

## Контекст
Team Notes розробляє одна людина (у майбутньому — невелика команда). Навантаження невелике:
десятки користувачів. Вже є один SvelteKit-застосунок і одна база PostgreSQL. Важливо швидко
змінювати продукт і просто деплоїти.

## Рішення
Один застосунок і один деплой. Код поділено на шари: `routes/` (presentation), `lib/notes/`
(ядро: типи, правила, схеми) і `lib/server/` (сервіс, репозиторії, сесії). Ядро не залежить
від інфраструктури — це перевіряє `npm run check:layers` у CI. Сховище підключається через
інтерфейс `NotesRepository` у `container.ts`.

## Наслідки
+ Прості транзакції в одній базі, один деплой, один набір логів.
+ Ядро тестується без бази; сховище замінюється в одному файлі.
− Не можна масштабувати частини окремо: застосунок масштабується цілком.
− Межі модулів тримаються на дисципліні та скрипті, а не на мережі.

## Альтернативи
- **Мікросервіси** (нотатки, користувачі, сповіщення окремо): відкинуто — для однієї людини
  і малого навантаження це мережеві збої, розподілені транзакції і кілька деплоїв без користі.
- **Моноліт без правил шарів:** відкинуто — правила швидко розповзаються по сторінках і SQL,
  а тести потребують бази для будь-якої перевірки.
